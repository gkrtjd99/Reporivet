# Document-driven native work

**선택적 운영 가이드다. Reporivet의 실행 기능이나 target 기본 정책이 아니다.**
기존 프로젝트에 없는 절차를 자동 설치하거나 모델·권한·CI 설정을 바꾸지 않는다.
제품 경계는 [ADR-0002](../decisions/ADR-0002-entrypoint-only-boundary.md)를 유지한다.

## 필요한 부분만 채택하기

프로젝트 소유자가 기존 문서에서 이번 작업의 기준을 지정하고, 현재 사용하는 하네스가 실행을 조율한다.
Claude Code + ultracode를 사용한다면 그 환경과 기존 API 연결을 유지한다.
네이티브 Workflows는 별도의 조율 기능이므로 이 안내를 고정 에이전트 호출 순서로 번역할 필요가 없다. [N1]

```text
짧은 진입점 → 작업에 해당하는 현재 근거 → 기존 하네스로 구현
           → 프로젝트의 실제 검사·리뷰 → 기존 계획에 결과·재개 정보 기록
```

1. 이미 있는 명세·계획·검사 안내의 원본을 찾는다. 이름이나 경로만으로 최신 계약이라고 추론하지 않는다.
2. 필요한 기준만 프로젝트의 기존 문서에 기록한다. 새 문서가 필요하면 이름과 위치는 소유자가 정한다.
3. 진입점에는 관련 문서의 위치와 적용 조건만 둔다. Reporivet 관리 블록 밖에 작성해야 갱신 시 보존된다.
4. 모델 선택을 조정할 때만 [라우팅 안내](model-effort-routing.md), Jev를 평가할 때만 [판단 안내](jev-decision-guidance.md)를 읽는다.

문서가 이미 잘 연결돼 있다면 추가하지 않는다. 전체 저장소나 세 가이드를 매 작업 전에 읽게 하지 않는다.
`@` import는 단순한 링크와 다르게 내용을 로딩하므로 모든 상세 계약을 시작 맥락에 넣는 용도로 쓰지 않는다. [N2]

## 작업 기준과 진행 기록

작고 국소적인 수정은 기존 이슈·명세와 검사만으로 진행할 수 있다.
공유 API, 영속 데이터, 보안, 여러 모듈, 장시간 작업처럼 인계가 중요한 경우에만 지속적인 계획을 둔다.
이 소스 저장소의 [계획 정책](../PLANS.md)은 참고 예이며 target에 강제되는 스키마가 아니다.

| 기록 | 필요한 내용 |
|---|---|
| Current Contract | 목표·제외 범위, 현재 원본과 revision, 수정 가능 영역·보호 영역, API·데이터 제약, 인수 조건 |
| Progress | 후보 커밋, 변경 사항, 실행한 검사와 결과, 미해결 문제, 남은 작업과 다음 판단 지점 |

진행 요약이 현재 계약을 대체하지 않는다. 구현 중 범위나 계약을 바꿔야 하면 변경 이유와 영향을 제시하고 기존 승인 절차로 돌아간다.
계획·이슈·Markdown이 이미 상태를 보관한다면 Reporivet용 작업 DB나 별도 상태 파일을 추가하지 않는다.

## 위임은 필요한 경우에만

고정 Main/Subagent 조직도, 모든 작업의 이중 리뷰, 최소 에이전트 수를 만들지 않는다.
위임이 유용한 작업에는 다음 정보를 기존 프롬프트나 작업 문서로 전달한다.

- 목표·제외 범위, 현재 근거의 위치와 revision, 필요한 실제 조항.
- 허용된 변경 영역, 필요한 도구·권한, 적용할 실행 프로필이 있는 경우 그 문서 참조.
- 선행 조건, 완료 검사, 중단·복귀 조건, 이미 승인된 실행·시간·비용 한도.

부모 대화가 전달된다고 가정하지 않는다. 경로만 전달하고 해당 내용을 읽었다고 간주하지도 않는다.
필수 계약은 검색 점수로 제외하지 않고, 선택적 예시나 스킬만 관련성에 따라 줄인다.

병렬 읽기와 병렬 쓰기는 구분한다. 쓰기는 변경 영역·기준 커밋·작업 공간·검사 데이터를 분리할 수 있을 때만 병렬화한다.
worktree는 보안 격리가 아니다. 공유 계약이나 migration 변경은 소유자와 통합 순서를 먼저 정한다.
Reporivet은 이 배정이나 격리를 실행하지 않는다.

## 검증·복구

완료 보고에는 정확한 후보, 실행한 명령·환경·exit status와 관련 결과를 남긴다.
`PASS`, `FAIL`, `UNPROVEN`을 구분하며, 미실행을 성공으로 기록하지 않는다.
결함을 찾았으면 실패 증거 → 허용 범위 안의 수정 → 같은 기준의 재검증으로 연결한다.
계약·권한 변경과 외부 부작용은 일반적인 코드 수정 재시도로 우회하지 않는다.

세션 재시작이나 컨텍스트 압축 후에는 현재 계약, 실제 diff, 마지막 후보와 검사 결과, 남은 문제를 다시 확인한다.
문서의 체크박스만 보고 이미 수행한 외부 변경을 반복하지 않는다. 통합 후에는 통합된 후보를 검증한다.
검토를 수행하지 못한 부분과 사람이 확인해야 할 부분은 그대로 남긴다.

## 지침·훅·관측의 경계

문서는 목표와 판단 기준이지 접근 통제 장치가 아니다. Claude의 `CLAUDE.md`도 맥락이며 강제 설정과 구분된다. [N2]
강제해야 하는 제한은 기존 권한·sandbox·프로젝트 검사에 두고, 부족한 특정 이벤트에만 훅을 검토한다.
모든 셸 조회나 도구 호출에 추가 승인을 부과하는 것을 기본값으로 만들지 않는다.
훅은 선택한 도구 경계에만 적용되며 문서 조회를 검사해도 계약 준수가 증명되지는 않는다. [N3]

스킬·디자인 지침은 필요한 작업에만 사용하고 출처·버전·권한을 확인한다.
브라우저는 UI 재현·회귀가 필요한 경우에 활용하고 API·계약 검사를 대체하지 않는다.
기존 로그나 telemetry가 있으면 작업·근거 revision·실제 모델·검사 후보를 연결한다.
원시 사고 과정 대신 짧은 선택 이유와 관측 증거를 남기며 비밀정보를 외부로 내보내지 않는다.
Reporivet은 새 스킬·훅·브라우저·OTel exporter를 설치하지 않는다.

## 효과 확인

같은 요구사항·계약·모델·effort·권한·평가 기준으로, 기존 하네스와 문서 진입점을 보완한 경우를 새 세션에서 비교한다.
Jev나 모델 라우팅을 추가한 조건은 별도로 측정해 문서 효과와 섞지 않는다.
완료 품질, 재작업, 불필요한 문서 읽기, 사람 대기, 전체 시간, 실패한 시도를 포함한 실제 비용을 기록한다.
기계적 링크 검사를 모델 성능 증거로 사용하지 않는다. 기존 [탐색 평가](agent-navigation-evaluation.md)도 향상을 입증한 실험은 아니다.
