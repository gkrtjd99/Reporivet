# Jev decision guidance

**Jev API 연결이나 자동 라우터가 아니라, 프로젝트가 선택적으로 채택할 판단 가이드다.**
Reporivet은 SDK·API 키·gateway·MCP·훅·큐를 설치하지 않고 모델 호출·청구·외부 전송도 하지 않는다.
Jev가 없어도 [문서 기반 작업](document-driven-native-work.md)은 기존 하네스로 진행한다.

## 역할과 출력의 의미

생성 모델은 계획·구현·설명을, Jev는 좁은 의미 판단을, 기존 코드·도구는 실행과 명시적 제한을 담당하도록 나눈다.
이 역할 분리는 선택적 설계다. Jev를 모든 판단 앞에 넣거나 최종 보안·완료 승인자로 사용하자는 뜻은 아니다.
공식 가이드도 제어 흐름·결정적 규칙·부작용을 코드에 남기고 작은 질문을 조합하도록 안내한다. [J1]

| 질문 유형 | 공식 출력의 의미 | 사용할 수 있는 예 |
|---|---|---|
| Choice | 제공한 선택지의 선택·확률분포와 confidence | 현재 가능한 작업 종류나 검토 경로의 후보 선택 |
| Score | 정의한 단계에 대한 점수·분포와 confidence | 요구사항 모호성이나 참고 문서 관련성 |
| Noul | 예·아니오 명제에서 '예'일 확률인 0–1 값 | 주어진 문단에 계약 변경 요구가 있는지 |

Choice/Score의 confidence는 분포의 집중도이지 작업 성공률이 아니다. [J2, J3]
Noul에는 별도의 confidence 필드가 없다. `0.5` 부근은 양쪽 가능성을 비슷하게 본다는 뜻이며 위험도 중간 점수가 아니다. [J4]
출력이 구조화되어도 판단이 옳다는 보장은 없다. `0.85` 같은 예제 임계값을 보편적인 운영 기준으로 복사하지 않는다.

## 적합한 지점과 맡기지 않을 지점

반복적인 작업 분류, 이미 검색된 참고 문서의 적합성, 승인된 [모델 프로필](model-effort-routing.md)의 후보 선택을 작은 실험으로 검토한다.
문서 검색·실제 읽기는 기존 도구가 수행한다. Jev가 파일 경로나 URL을 받았다고 본문을 조회했다고 가정하지 않는다.
필수 API 계약은 관련성 평가로 제거하지 않는다.

파일 존재·해시·계약 revision·예산 산술·권한·시간 비교·테스트 exit status는 코드 또는 기존 프로젝트 검사로 확인한다.
계약 변경, 배포·병합, 비밀정보 전송과 같은 권한을 확률값으로 승인하지 않는다.
정확한 계산·날짜 비교·다단계 추론 및 적대적 입력의 한계는 공식 문서에 명시돼 있다. [J5]

## 판단 기준을 문서로 정하기

프로젝트의 기존 계획이나 정책 문서에서 필요한 항목만 정한다. 강제 파일명·frontmatter·새 상태 원장은 없다.

| 항목 | 내용 |
|---|---|
| 목적·범위 | 반복해서 필요한 판단 한 가지와 사용하지 않을 상황 |
| 근거 | 현재 목표·관련 계약 본문·관련 변경 또는 실패 증거와 revision |
| 질문 | instructions, 선택지/단계별 의미, 경계 사례 |
| 후보 | 현재 허용된 선택지와 명시적인 '해당 없음/추가 근거 필요' 경로 |
| 불확실성 | 평가한 임계값과 검토 조건; 미평가면 자동 적용하지 않음 |
| 적용 주체 | 결과를 참고하는 기존 host/사용자와 우회할 수 없는 권한·검사 |
| 실패·갱신 | 오류·미지원·오래된 입력·상충 결과 처리와 재평가 조건 |
| 증거 | 질문·기준·모델 버전, 실제 결과, 후속 실행과 독립 검증 |

예: '최적 모델과 effort와 병렬 실행 수를 모두 결정하라' 대신 작업 유형·모호성을 따로 묻는다.
이름만으로 의도를 전달하지 말고 질문 본문과 선택지에 기준을 쓴다.
실제 모델 배정은 사용 가능성·품질·예산 규칙을 확인한 뒤 기존 실행 환경에서 수행한다.

## 입력과 실패 처리

`state`에는 판단에 필요한 실제 조항과 증거를 넣고 전체 대화·저장소를 그대로 보내지 않는다.
필수 정보가 부족하면 먼저 보충한다. 요약만으로 판단하는 경우 원본 참조와 누락 가능성을 남긴다.
같은 요청의 질문은 같은 state를 독립적으로 평가하므로 앞 질문의 답을 뒤 질문이 읽는다고 가정하지 않는다. [J6]
앞 판단 후 추가 검색이 필요하면 자료를 확보한 뒤 별도 요청으로 다룬다.

기존 연결이 제공하는 응답을 사용할 때는 실제 SDK/API 버전에 맞는 출력 필드를 확인한다.
필수 답변 누락, 알려지지 않은 선택지, 비유한 값, 범위 밖 확률, 파싱 실패, 인증·네트워크·timeout 오류를 성공으로 취급하지 않는다.
실패 시 이미 허용된 기존 하네스 경로를 유지하거나 검토로 보내고, 위험한 작업의 승인 조건은 그대로 유지한다.
검증되지 않은 모델로 몰래 대체하거나 예산 없이 반복 재시도하지 않는다.

입력 계약·후보·권한·모델·질문이 바뀌면 이전 판단을 재사용하지 않는다.
캐시를 운영하는 기존 도구가 있다면 입력과 질문·정책·모델 버전을 함께 식별하고 유효성을 재확인한다.
Reporivet이 이를 자동 집행하거나 캐시를 제공하는 것은 아니다.

## 관찰 모드부터 평가하기

1. **미연결:** Jev를 호출하지 않는다. 문서만 추가했다고 연동 완료로 보고하지 않는다.
2. **관찰:** 데이터 전송·비용이 승인된 기존 연결에서 호출하되 실제 실행 경로는 바꾸지 않는다.
3. **제한 적용:** 한국어 작업을 포함한 평가가 끝난 저위험 판단에만 적용한다. 품질이 낮아지면 기존 경로로 되돌린다.

질문을 다듬는 사례와 최종 평가 사례를 분리하고, 기본 하네스·문서 보완·Jev 추가 조건을 구분한다.
같은 요구사항·검사·실행 한도에서 잘못된 라우팅, 추가 검토 누락, 정상 작업 오차단, 완료 품질, 전체 시간·비용을 기록한다.
API 응답속도만으로 개발 속도를 주장하거나 다른 데모의 수치를 이 프로젝트 실측으로 사용하지 않는다.

## 데이터·언어·관측

공식 문서는 텍스트 입력을 지원하고 영어가 가장 강하며 한국어를 포함한 다른 언어는 별도 평가가 필요하다고 설명한다. [J6, J7]
브라우저 스크린샷을 직접 판정한다고 가정하지 않는다. 승인된 텍스트/DOM/오류 증거만 전달하거나 적합한 다른 도구로 검증한다.
악의적 문서의 지시가 판단에 영향을 줄 수 있으므로 명시적 권한 제한을 별도로 유지한다. [J5]
외부 전송 전 비밀키·개인정보·비공개 계약의 허용 범위와 제공자의 보존 정책을 확인한다.

기존 진행 기록에 필요한 작업/후보 참조, 자료 revision, 질문 버전, Jev 원본 결과의 보호된 참조,
실제 선택, 적용한 규칙, 후속 검사·수정 결과를 연결한다. 새 telemetry 저장소를 요구하지 않는다.
Jev가 생성하지 않은 설명을 원래 판단 이유로 꾸미지 않는다. LLM의 사후 설명은 사후 분석으로 표시한다.

계정 접근성·가격·gateway 모델 ID·SDK 응답 모양은 도입 시 공식 문서와 실제 계정에서 다시 확인한다.
가입 일시 중단이나 데모 가격을 영구적인 제품 계약으로 기록하지 않는다.
이 문서는 실호출·성능·현재 계정 가용성을 검증한 보고서가 아니다.
