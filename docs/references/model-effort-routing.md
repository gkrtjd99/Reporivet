# Model and effort routing

**문서로 실행 기준을 정리하는 가이드이며 라우터 구현이나 설정 파일이 아니다.**
Reporivet은 모델을 호출하거나 `.claude` 설정, 환경변수, API gateway를 수정하지 않는다.
[문서 기반 작업 안내](document-driven-native-work.md)에서 모델 선택이 실제로 필요한 경우에만 이 문서를 읽는다.

## 하네스와 모델을 구분하기

Claude Code + ultracode를 유지하면서 API gateway에서 실제 모델을 대치하는 환경을 대상으로 한다.
`Fable → Astra`는 요청자가 설명한 로컬 매핑의 예일 뿐, 공식 모델 ID나 제공자 공통 매핑이 아니다.
Astra를 호출한다는 이유로 Codex SDK나 별도 실행 루프를 추가하지 않는다.

공식 문서는 ultracode를 `xhigh` 요청과 Workflows 조율을 결합한 설정으로 설명하며,
같은 effort 이름도 모델마다 같은 추론량을 의미하지 않는다고 명시한다. [M1]
서브에이전트의 모델·effort 설정은 네이티브 기능이지만 허용 모델, 상속, 상위 설정에 의한 대체를 확인해야 한다. [M2]

비Claude 모델로의 대치는 Claude Code의 공식 지원 범위가 아니다. 현재 연결이 작동하더라도
도구 호출·구조화 결과·중단·재개·effort 전달의 동일성까지 보장된 것으로 취급하지 않는다. [M3, M4]

## 최소한의 선택 원칙

다음은 채택 여부를 프로젝트가 결정하는 정책 제안이다.

| 상황 | 먼저 할 일 |
|---|---|
| 정해진 파일 조회·계산·검사 | 기존 도구를 사용한다. 모델을 고르기 위한 추가 LLM 호출부터 만들지 않는다. |
| 목표·범위·API 설계가 모호함 | 승인된 고성능 프로필로 계획을 보완하고 현재 계약을 확정한다. |
| 범위·계약·인수 검사가 명확한 구현 | 자체 평가를 통과한 프로필 중 완료 비용이 적합한 것을 선택한다. |
| 공유 계약·보안·영속 데이터 변경 | 영향과 승인부터 확인한다. 높은 effort가 권한을 대신하지 않는다. |
| 구현 실패 | 자료 누락·환경 오류·계약 충돌·구현 오류를 분리한 뒤 필요할 때만 프로필을 상향한다. |

Astra·Fable·Sol·Luna는 후보를 논의하는 이름으로 사용할 수 있으나, 이름 자체로 난이도 등급을 고정하지 않는다.
특히 **“Luna는 xhigh 이상에서 충분한 품질이며 Sol보다 완료 비용이 낮다”는 초기 검증 가설**이다.
지원되는 effort, 실제 매핑과 작업별 평가를 확인하기 전에는 공통 기본값이나 성능 보장으로 채택하지 않는다.

## 프로필은 기존 문서에 기록하기

아래는 사람이 검토할 항목이다. Reporivet이 파싱하는 YAML/JSON 스키마가 아니며 별도 registry를 요구하지 않는다.

| 항목 | 기록할 내용 |
|---|---|
| 적용 범위 | 작업 종류·제외 조건, 요구되는 도구와 컨텍스트, 프로필 revision |
| 요청 설정 | 하네스와 버전, 요청 모델 이름, 요청 effort |
| 변환 설정 | gateway 규칙 revision, 목표 upstream ID, effort 변환 규칙 |
| 관측 결과 | 실제 전송 필드, 제공자가 보고한 모델·사용량, 관측 가능한 적용값과 `unknown` |
| 품질 기준 | 해당 작업군의 테스트·회귀·리뷰, 최소 effort의 평가 근거 |
| 제한 | 기존 권한, 병렬 실행·재시도·시간·비용 한도와 집행 주체 |
| 실패 경로 | 미지원·불확실·예산 초과 시 기존 검증된 설정 유지 또는 승인된 검토 경로 |

희망값, 전송값, 제공자가 보고한 값, 실제 품질을 구분한다.
`xhigh`를 요청한 로그만으로 upstream이 같은 의미로 적용했다고 기록하지 않는다.
관측할 수 없는 값은 추정해서 채우지 않는다. 비밀키·실제 인증 헤더는 문서에 저장하지 않는다.

## 실제 적용은 기존 환경에서 별도로 확인하기

1. 승인된 기존 프로필이 있으면 그대로 시작한다. 문서만 추가했다고 라우팅이 켜졌다고 하지 않는다.
2. 서로 다른 프로필을 시험할 때 요청별 모델·effort가 실제로 구분되는지 작은 작업으로 확인한다.
3. 필요한 기능이 없거나 설정이 대체되면 명시적으로 보고한다. 지원하지 않는 옵션을 조용히 무시하지 않는다.
4. 작업 또는 재시도 경계에서 변경한다. 병렬 실행 중 전역 alias 매핑을 바꾸어 다른 작업에 영향을 주지 않는다.
5. 중계기·모델·하네스 버전이 바뀌면 관련 도구 사용·검증·비용 회귀를 다시 확인한다.

네이티브 Workflows 내부의 모든 실행에 사용자 정의 서브에이전트 파일이 자동 적용된다고 가정하지 않는다.
호출 경로에서 지원하는 설정과 실제 이벤트를 확인하고, 내부 설정을 통제할 수 없다면 기존 검증된 경로를 사용한다.
저비용 프로필이나 Jev가 없어도 일반적인 문서 기반 작업은 계속 가능해야 한다.

## 선택적 Jev와 기존 정책

문서 관련성·작업 유형 같은 반복적인 의미 판단에만 [Jev](jev-decision-guidance.md)를 검토한다.
후보는 현재 사용 가능하고 권한·기능·예산 조건을 충족하는 프로필로 한정한다.
Jev의 선택은 추천값이며 실제 설정 변경은 승인된 host/gateway 연결이 맡는다.
프로필 추천이 승인 범위, 계약, 최소 품질 기준이나 예산을 완화하지 못하게 한다.

모델 변경, 더 높은 effort, 추가 리뷰를 매 실패의 기본 해결책으로 사용하지 않는다.
기본 하네스가 충분히 수행하는 작업에는 새 판단 호출이나 고정 이중 리뷰를 추가하지 않는 선택도 포함한다.

## 평가와 중단 기준

동일한 기준 커밋·계약·실제 모델/effort·권한·검사로 반복 비교하고, 프로필을 바꾸는 실험은 바꾼 변수를 명시한다.
한국어 지침, 도구 오류, 부족한 문서, 재시작, 계약 변경 사례도 포함한다.
측정값은 첫 시도 성공률, 최종 결함, 정상 작업 오차단, 재작업, 사람 개입, 전체 완료 시간과 실제 upstream 총비용이다.
비용에는 실패·재시도·검토와 gateway 비용을 포함하고, 성공 결과만의 토큰을 골라 집계하지 않는다.

속도·비용이 나아져도 품질 기준을 못 맞추면 채택하지 않는다.
정상 작업을 자주 막거나 전체 완료 비용이 증가하면 기존 프로필로 되돌리고 원인을 기록한다.
이 문서에는 실측된 프로필 비교나 최적 effort 결과가 없다.
